# Карьерный агент — вакансии hh.ru через LLM-агента

Экзаменационный проект по обработке естественного языка: чат с AI-агентом, который подбирает
вакансии под профиль соискателя через открытый API hh.ru, считает разрыв в навыках и зарплатную
статистику, готовит письма работодателям и ведёт учёт откликов.

## Возможности

| Функция | Как работает |
|---|---|
| Подбор вакансий | FTS-поиск по датасету (585k+ вакансий) + семантический поиск по смыслу (TF-IDF + LSA) + прозрачный скор матчинга профиля |
| Похожие и свежие | «Похожие вакансии» по косинусной близости LSA-векторов; «свежие за N дней» — новые вакансии, ранжированные под профиль |
| Разрыв в навыках | Доля навыков рынка в стеке профиля, приоритеты (высокий/средний/низкий) |
| Статистика зарплат | P25 / медиана / P75 «на руки» по навыку/городу/опыту + динамика медианы по месяцам — своим датасетом |
| Письма работодателям | Генерация текста агентом, сохранение **только локально**; правка текста, перегенерация, переименование, скачивание .txt и кнопка «копировать» |
| Учёт откликов | Локальный трекер со статусами и напоминаниями («связаться позже»), экспорт CSV; вакансию можно найти поиском |
| Чат с агентом | Мультиагент (координатор + 3 суб-агента), SSE-поток: ход рассуждений, вызовы инструментов; названия диалогов, удаление; память — сжатие истории в сводку |
| Профиль соискателя | Синтетические данные из PDF-резюме (офлайн-разбор `tools/parse_resume.py`), правка в интерфейсе |
| Evals | `tools/run_evals.py`: эталонные вопросы, отказы off-topic/инъекций, ожидаемые инструменты, анти-галлюцинация чисел, опционально LLM-as-judge |

## Ключевые ограничения (по постановке)

- **Только чтение hh.ru.** Application-токен, в коде только `GET`-запросы; персональные данные
  соискателей через API физически недоступны (`403 user_auth_expected`, проверено живьём).
- **Никакой автоматической отправки.** Ни отклики, ни письма никуда не отправляются — инструментов
  для этого не существует в принципе (отсутствующая возможность сильнее обещания). Тексты копирует
  и отправляет сам соискатель.
- **Синтетические данные соискателя** на основе реального резюме (PDF в репозиторий не входит).

```
  search_vacancies   match_profile     skill_gap       salary_stats       draft_letter → outbox/
```

### Guardrails в три слоя
1. **Детерминированный пред-фильтр** — формы инъекций («забудь инструкции», «выведи промпт»…) →
   отказ без вызова модели;
2. **Системный промпт** — белый список тем, фиксированная фраза отказа, «каждая цифра — из
   инструмента»;
3. **Пост-фильтр** — утечка системного промпта (8-словные шинглы) и заявления о «отправленных»
   письмах/откликах → замена ответа отказом.

### Многопользовательность
Изоляция по `user_id` из токена: свои сессии диалогов (ADK `DatabaseSessionService`), свои письма
(`data/outbox/<user>/`) и свои отклики. Пароли — PBKDF2-HMAC-SHA256 + соль, токены — случайные,
в БД только хэш. Пустые диалоги (без сообщений) не сохраняются; названия диалогов генерируются
из первого сообщения и переименовываются пользователем; диалоги удаляются через модальное окно.

### Память длинных диалогов
ADK хранит всю историю сессии и отдаёт её модели целиком — при длинном диалоге контекст
переполняется. Перед ходом история сверяется с бюджетом (`app/memory.py`): старая часть диалога
сжимается LLM в короткую сводку (факты, города, id вакансий, цифры), старые события заменяются
сводкой, последние реплики остаются как есть. Сжатие видно в интерфейсе как событие
«память: …»; при недоступности модели работает детерминированный фолбэк.

## Стек

Python 3.11 · Google ADK · FastAPI + uvicorn · SQLite (FTS5, WAL) · litellm (OpenAI-совместимый
провайдер) · vanilla JS фронтенд · pytest

## Запуск

```bash
# 1. окружение (один раз); все зависимости зафиксированы в requirements.txt
py -3.11 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt

# 2. .env рядом с проектом (НЕ коммитится):
#    OPENAI_API_KEY=...  OPENAI_BASE_URL=...  MODEL=...
#    HH_CLIENT_ID=...  HH_CLIENT_SECRET=...  HH_ACCESS_TOKEN=...  HH_USER_AGENT=...

# 3. собрать датасет в SQLite (данные не в git — восстанавливаются сборщиком)
.venv\Scripts\python tools\collect_hh.py --period 7      # свежие вакансии с hh
.venv\Scripts\python tools\clean_merge.py               # слои Kaggle + API -> единый CSV
.venv\Scripts\python tools\build_db.py --full           # data/app.db + FTS + агрегаты
.venv\Scripts\python tools\build_semantic.py            # семантический индекс (TF-IDF + LSA)

# 4. сервер + интерфейс
run_server.bat          # или: .venv\Scripts\python -m uvicorn app.server.main:app --port 8000
# откроется http://127.0.0.1:8000 (Swagger: /docs)
```

Ежедневное обновление датасета: `daily_collect.bat` (сбор за сутки → догрузка описаний → импорт).

## Тесты

```bash
.venv\Scripts\python -m pytest tests/ -q
```

89 тестов: guardrails (инъекции RU/EN, утечка промпта, запрещённые заявления), инструменты
(лимиты выдачи, квантили, локальные записи), авторизация, изоляция пользователей, SSE-конверт,
диалоги (пустые не сохраняются, удаление/переименование), письма (разбор файла, правки),
память (сжатие истории), классификатор тем, семантический поиск, динамика зарплат,
напоминания откликов, профиль, evals-проверки, разбор резюме (город по «Проживает»,
места работы «компания + опыт», секция «Опыт работы»), словарь навыков (только из БД),
счёт по опыту работы.

## Evals (оценка качества)

```bash
.venv\Scripts\python tools\run_evals.py            # метрики: отказы, инструменты, анти-галлюцинация
.venv\Scripts\python tools\run_evals.py --judge    # + LLM-as-judge (1–5 по рубрике)
```

Эталон — `evals/benchmark.json`, отчёт — `data/reports/eval_<дата>.md`.

```
  runner_cli.py      консольный прогон

tests/               pytest

```
